# ZUVYR Security Diagnostics Learning Foundation

Status: SOURCE-ONLY FOUNDATION — does not change the active PACK089 gate or authorize PACK090.
Date: 2026-09-23

## Purpose

This foundation adapts safe architectural ideas from `0x6rss/chat-apps-osint` into ZUVYR without ingesting captured peer metadata into model training. The upstream repository is MIT licensed, but code-license rights are separate from rights over any real captured user/peer data.

Upstream reference: https://github.com/0x6rss/chat-apps-osint

No upstream implementation code or captured data is vendored by this change. ZUVYR uses its own policy, normalized synthetic schema, evaluation corpus and future adapter contract.

## Canonical integration points

- PACK047 Permission Center remains the authorization authority for any future diagnostic execution.
- PACK089 unified tool runtime remains the authority for future diagnostic adapters/plugins.
- PACK094 Learning Pipeline remains the authority for training rights, privacy admission, Failure Bank and consent.
- PACK095 Model Lab remains the authority for datasets, holdouts, benchmarks and checkpoint lineage.
- PACK096 owned-model runtime remains the authority for training/serving rollout.

This change does not mark any Pack complete or reopen historical Packs. PACK089 remains blocked on its existing external Google OAuth production-acceptance gate.

## Data-use classes

### SAFE_SYNTHETIC

Generated by ZUVYR with documentation/reserved addresses only. It may be used for model development after train/eval split separation. The same sample must not be admitted to both training and the independent holdout.

### PUBLIC_NON_PERSONAL

Public code, documentation or non-personal reference material. Training still requires the canonical PACK094 rights/license, provenance, privacy and training-consent gates. It must not contain captured peer telemetry.

### AUTHORIZED_DIAGNOSTIC

Real diagnostic output collected for an explicitly authorized user/session. Runtime-only. It can be interpreted to help that user, but it does not become training or benchmark data merely because global training consent is enabled.

### PERSONAL_SENSITIVE

Real IP addresses, exact coordinates, phone/JID identifiers, call/session IDs, persistent device/correlation fingerprints, or raw time series linked to a person/session. Blocked from training and benchmark datasets. Runtime use requires explicit authorization and scoped handling.

### BLOCKED_FROM_TRAINING

Unknown provenance, unauthorized capture, unsafe synthetic fixtures using arbitrary public IPs, or unsupported classification. Fail closed.

## Training policy

Allowed knowledge classes:

- synthetic NAT/CGNAT/IPv4/IPv6/relay reasoning;
- networking and VoIP concepts;
- structured telemetry reasoning;
- privacy-preserving explanation patterns;
- defensive reverse-engineering concepts;
- fail-closed version/build behavior;
- remediation guidance;
- rights-verified public non-personal reference material through PACK094.

Forbidden from training:

- real public/private IPs;
- exact coordinates or exact-location claims;
- phone numbers or JIDs associated with a real person;
- call/session IDs;
- persistent device fingerprints or A/B correlation buckets;
- raw event streams from real sessions;
- raw speech/audio activity series linked to a real user;
- any real diagnostic capture merely because training consent exists.

Runtime authorization and training rights remain separate authorities.

## Evaluation policy

The independent holdout is synthetic-first and excluded from training. It must test:

- network semantics and CGNAT/private/public reasoning;
- uncertainty calibration;
- prevention of street/exact-location overclaims;
- unsupported identity/phone/JID inference;
- unknown-build fail-closed behavior;
- missing or contradictory telemetry;
- privacy admission;
- diagnostic-adapter permission and sandbox rules.

Real personal telemetry is not an evaluation-benchmark source.

## Synthetic data

`backend/lib/securityDiagnosticsLearning.js` generates deterministic synthetic scenarios using documentation-safe address ranges. Arbitrary public IP literals fail closed.

A dataset generator must write new files only and never silently overwrite an existing training/eval artifact.

## Future diagnostic adapter contract

Any future live diagnostic adapter must require:

- explicit user authorization;
- Permission Center scope;
- isolated/sandboxed execution;
- bounded network egress;
- no raw ZUVYR/provider-secret access;
- structured output;
- audit events;
- STOP/kill behavior and timeout;
- fail-closed behavior for unsupported versions/builds;
- no persistent raw capture;
- no cross-user reuse.

The current foundation deliberately does **not** wire a live Frida/WhatsApp capture tool into production.

## User-outcome contract

USER_VALUE: Explain authorized network/VoIP/device diagnostics accurately, expose uncertainty, and turn findings into concrete privacy/reliability remediation.

EXECUTABLE_USER_ACTIONS: A future authorized adapter may run a scoped diagnostic, create a redacted report, validate a protection setting, and retest after remediation. No live capture is enabled by this source-only foundation.

MONEY_OPPORTUNITY_RELEVANCE: INDIRECT.

MONEY_OPPORTUNITY_NOTES: The foundation can support defensive diagnostics, managed support and security workflows. It must not become a people-tracking capability and does not promise income.

NEXT_BEST_ACTION: After an authorized diagnostic result, propose the most relevant remediation or verification step, such as enabling IP protection where available, changing/retesting the network, reviewing exposed metadata, or exporting a redacted report.

SUGGESTION_CHIPS: Derived from the current finding; static generic OSINT/tracking chips are not allowed.

PROVENANCE_BEHAVIOR: Separate observed telemetry, coarse inference and unsupported inference. Exact location/identity claims are never promoted from weak metadata.

PERSONALIZATION_BEHAVIOR: May prioritize remediation using authorized device/session context; may not broaden collection scope.

HARD_STOP_IMPACT: Defensive analysis remains available. Unauthorized collection, persistent tracking and abusive use are not enabled by this foundation.

OUTCOME_TESTS: Must verify real-diagnostic runtime-only handling, training/eval isolation, documentation-safe synthetic addresses, privacy admission, unsupported-inference limits, fail-closed build handling and adapter security.
