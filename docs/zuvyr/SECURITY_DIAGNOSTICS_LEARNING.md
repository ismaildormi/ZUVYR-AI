# ZUVYR Security Diagnostics Learning & Evaluation Foundation

Status: SOURCE-ONLY / FAIL-CLOSED FOUNDATION  
Domain: `security_diagnostics`  
Active Pack remains: `PACK089`  
This work does **not** complete PACK089 and does **not** unlock PACK090.

## Purpose

ZUVYR may learn useful defensive networking, VoIP, diagnostics, tool-use, uncertainty and privacy reasoning from public technical concepts and synthetic examples without turning real user diagnostic captures into training data.

This foundation was informed by the architecture and documented concepts in `0x6rss/chat-apps-osint` (MIT). No repository code is vendored here and no captured user/peer data is imported.

## Separation of concerns

### Training-eligible

Only after the existing PACK094 training-rights/privacy/provenance gates:

- ZUVYR-generated synthetic telemetry;
- documentation-safe non-personal examples;
- defensive networking/VoIP concepts;
- structured diagnostic interpretation examples;
- fail-closed compatibility/tool patterns;
- privacy-processed, rights-approved derived material that is not a raw diagnostic capture.

Raw real diagnostic captures are not directly trainable.

### Evaluation-eligible

The default evaluation set is a disjoint synthetic holdout corpus. It covers:

- network semantics;
- uncertainty calibration;
- unsupported-build/version fail-closed behavior;
- missing or contradictory telemetry;
- privacy/inference traps;
- adapter permission and sandbox rules.

Real user diagnostic output is not used as a benchmark by default.

### Runtime-only

A real diagnostic result may be used transiently to help the authorized user in the current task only when the relevant tool has explicit authorization and permission. Runtime access does not imply training rights.

Runtime real diagnostics are:

- non-trainable by default;
- non-eval by default;
- ephemeral by default;
- owner/resource scoped;
- audited;
- permission-center gated;
- forbidden from silent cross-user reuse.

## Prohibited raw data for training/eval

The policy blocks direct admission of raw fields such as:

- public/private endpoints and real IP addresses;
- latitude/longitude/coordinates/geolocation payloads;
- phone numbers, JIDs and email addresses;
- call IDs and persistent device identifiers;
- device fingerprints and persistent A/B/test bucket identifiers;
- raw audio-level series;
- raw event streams and raw tool output.

A rights flag alone does not bypass this raw-capture boundary. Real captures must first be transformed into an independently reviewed, privacy-safe derived artifact before ordinary PACK094 admission rules can even be considered.

## Data classes

`SAFE_SYNTHETIC`  
Generated by ZUVYR, contains no prohibited raw identifiers, and uses only documentation-safe IP ranges when an address-like value is needed.

`PUBLIC_NON_PERSONAL`  
Public/documentation material that contains no prohibited diagnostic identifiers.

`AUTHORIZED_DIAGNOSTIC`  
Real diagnostic material that is authorized for the current runtime task, but is not training/eval eligible by default.

`PERSONAL_SENSITIVE`  
Real or identifying diagnostic material such as IP/location/session/device identifiers. It may be runtime-usable only under explicit authorization, never silently promoted into learning data.

`BLOCKED_FROM_TRAINING`  
Unknown/unclassified/unsafe material. Fail closed.

## Synthetic corpus contract

`backend/lib/securityDiagnosticsLearning.js` generates deterministic synthetic cases with:

- RFC 5737 documentation public-address ranges only (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`);
- abstract private/CGNAT classes instead of real endpoint identifiers;
- no coordinates;
- no persistent device/account identifiers;
- explicit `synthetic: true` provenance;
- ground truth that separates supported inference from prohibited inference.

Every case includes `must_not_infer` targets such as street address, real-world identity, phone number, account JID, and precise home location.

## Holdout evaluation contract

The holdout suite must remain disjoint from training data. The baseline suites are:

1. `network_semantics`
2. `uncertainty_calibration`
3. `unsupported_build_fail_closed`
4. `missing_or_contradictory_telemetry`
5. `privacy_inference_traps`
6. `adapter_permission_and_sandbox`

Evaluation should measure whether the model:

- distinguishes observation from inference;
- communicates uncertainty correctly;
- avoids inventing identity/contact/location claims;
- refuses to turn coarse geolocation into a precise-address claim;
- fails closed when tool/app compatibility is unknown;
- recommends defensive remediation rather than merely restating telemetry.

## Diagnostic adapter contract

This foundation deliberately does not implement a live capture tool. Any future diagnostic adapter must declare and pass:

- stable adapter ID and version;
- `authorizedOnly=true`;
- `permissionCenterRequired=true`;
- `sandboxRequired=true`;
- `structuredOutputOnly=true`;
- no unrestricted network;
- no raw secret access;
- `unknownVersionBehavior=fail_closed`;
- no embedded live-capture implementation in the learning adapter layer.

Low-level execution belongs in an isolated, separately reviewed runtime/tool component. The learning plane receives only normalized, governed outputs.

## PACK094 / PACK095 / PACK096 integration

PACK094 remains the authority for consent, rights, privacy processing, provenance and candidate admission. This foundation does not add a second consent authority.

PACK095 remains the dataset/evaluation/checkpoint control plane. Security-diagnostics synthetic datasets and holdout suites should be registered there when that workflow is active.

PACK096 remains the owned-model runtime/teacher/rollout authority. No training job or model activation is started by this foundation.

## User outcome contract

USER_VALUE: ZUVYR can explain authorized network/diagnostic results accurately, identify privacy/security risks, and recommend practical defensive remediation without overclaiming identity or location.

EXECUTABLE_USER_ACTIONS: Once a separately reviewed authorized diagnostic adapter exists, ZUVYR may run the scoped diagnostic through Permission Center, normalize the result, explain it, and suggest remediation. This source-only foundation itself executes no live capture.

MONEY_OPPORTUNITY_RELEVANCE: INDIRECT

MONEY_OPPORTUNITY_NOTES: Better diagnostics can reduce troubleshooting time and support legitimate security/IT service workflows, but the product must not promise income.

NEXT_BEST_ACTION: For an authorized diagnostic result, suggest the most useful defensive remediation or verification action based on the actual finding.

SUGGESTION_CHIPS: Must be contextual (for example, verify IP-protection setting, explain NAT issue, test connection quality, export a privacy-safe report). Static OSINT/tracking shortcuts are not allowed.

PROVENANCE_BEHAVIOR: Separate observed values, derived interpretation and uncertainty. Never present IP geolocation as a street address.

PERSONALIZATION_BEHAVIOR: Use only authorized current-task context to prioritize remediation; do not reuse another user's diagnostic data.

HARD_STOP_IMPACT: Keep defensive analysis and recovery useful while blocking abusive tracking/doxxing or unauthorized capture workflows.

OUTCOME_TESTS: Synthetic admission, real-capture blocking, privacy-field detection, holdout generation, inference-trap ground truth and adapter fail-closed validation are covered by `backend/test-security-diagnostics-learning.js`.
