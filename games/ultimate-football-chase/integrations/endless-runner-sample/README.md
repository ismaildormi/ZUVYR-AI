# Independently authored Unity sample add-on — first integration patch

This folder contains **only new MIT-licensed code written for this project**. It does not embed, vendor, modify, sublicense or redistribute `Unity-Technologies/EndlessRunnerSampleGame` code/assets. Copy **only** this folder's `Assets/UFCAddOn/` into an owner-provided local installation of that Unity sample after determining that the owner has the rights needed for that installation and resulting distribution. It cannot compile in the isolated `ultimate-football-chase` Unity project by itself: it intentionally references the sample's `Character` component. It is not a completed game or a replacement for the existing project. Do not import the old project's cat, train, sound, font, textures or UI into this repository as MIT files.

## Integration in a locally installed copy of the sample

1. Open a separate local Unity checkout of the exact upstream snapshot `8a11421d45637c1565508c55548b959a1a58ace8` using the Unity version/dependencies appropriate for that sample, including its Addressables and Git LFS data. Establish a clean compile first. The existing separate Unity 6 project is **not** a drop-in merge target for its old URP/Addressables/ads/IAP architecture.
2. Copy `Assets/UFCAddOn/` to the sample's `Assets/UFCAddOn/`. No edits to `Assets/Scripts/` in the sample are needed for this first visual add-on. Create **Football Chase Add-On > Runner Identity Palette** in Unity's asset menu. Set original colours. Add `SampleCharacterIdentity` to a separately authored humanoid character prefab that already has the sample's `Character` component; assign the palette, distinct shirt/skin renderers and optional headwear objects (index 0 = no headwear). Keep the sample character collider/controller and its movement scripts unchanged. A runtime wardrobe UI can call `SelectStyle(shirtIndex, complexionIndex, headwearIndex)`; there is **no persistence, purchase or entitlement** in this patch.
3. Select the prefab and run **Tools > Football Chase Add-On > Validate Selected Humanoid**. Configure a unique fictional `Character.characterName`, a cleared icon, sounds and humanoid Animator Controller matching the sample's existing parameter names (`Dead`, `Moving`, `Jumping`, `JumpSpeed`, `Sliding`) and `runStart` state. Add the sample's Addressables label `characters` and update the character inventory/selection flow with an explicit data migration; renaming an existing registered character at runtime would break lookups and saved player data. Inspect the purchased/sample shop integration locally before selling anything. Test mobile swipe, the three lanes, collision/jump/slide, rewards, shop, Addressables resolution, and build viability on real devices.

## Why the full base was not committed here

The upstream repository does not provide a project-wide MIT license; its third-party notice describes Asset Store EULA terms. Accepting legal responsibility does not turn upstream code/assets into MIT-redistributable files. The MIT license in *this directory* applies only to this new add-on; it does not change the scope of any sample or parent-repository license. This add-on is additive and does not yet implement the PDF-specific speed progression (the sample defaults to 5 m/s and uses a different speed curve), revival rules, VAR, a validated shop/wallet or final 3D art. Those require a separately authorized and Unity-compiled base, migration/QA and explicit owner decisions; do not represent this as store-ready.
