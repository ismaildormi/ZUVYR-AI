# Phase 9 — scope extension (source-only)

**Historical snapshot:** Phase 10 subsequently added a local x1–x30 mission chain, runner route palettes, five greybox colour treatments per character and guest reset. See [current status](PHASE10_STATUS.md) for remaining gaps.

This phase is **source-implemented, not Unity-compiled or device-accepted**. The isolated project remains in this repository. No separate repository was created. Read earlier phase documents for gameplay implementation and their own acceptance gaps.

## Added / changed

- **Showdown boundary:** The Hub has a noticeboard and fixed-document, server-read-only `eventViews/showdown_current` schedule gateway. It validates 3–5-day UTC durations and bounded public text; missing SDK/document/network or malformed payload is **UNAVAILABLE**. The example Firestore rules allow that one public document read, deny client writes/lists. No entries, asynchronous opponents, victory, unlock or prize methods exist. Structural validation is not proof of a real contest. A trusted publisher and event verification are prerequisites.
- **Original content:** `OriginalRoster` defines four fictional named silhouettes with different greybox accessories, selectable in the Hub wardrobe and runner, with three freely selectable greybox tints. `FictionalLeague` contains eight original team-name/colour concepts, listed on a Hub board. Four one-time text story beats are gated at stages 0, 11, 21, 31; stage completion is still the *untrusted preview* described in phase 4. No likenesses, logos or real clubs were imported. Team kit art and proper animated characters are not claimed.
- **Missions:** Three UTC-day local/account **preview checklists** (one run, 20 coins, 500m) reset at a UTC boundary and display in the Hub. No scoring multiplier, prize, server-verified credit or spendable reward is issued; neither clock nor run distance is authoritative.
- **Settings and sound:** Separate game-music and SFX AudioSources; original procedural four-second prototype pulse and coin/jump/impact cues; two separate UI volume sliders; mobile impact haptics toggle; persistent `Use My Music` mutes **only game music**, never SFX; preference stored with the current guest or signed-in Hub profile. The iOS native hook requests `AVAudioSessionCategoryAmbient` (including when toggled on). The C# game code never requests exclusive Android audio focus; Unity player/OS behavior still needs real-device verification. No access to a user's music library. Language selection persists (`en` initially; selectable `ar`, `fr`, `en`), region defaults to `MA` and is editable as `OTHER` (a preference, **not** prize eligibility). Small original UI/story translation starter exists, **not full localization**; legacy uGUI fonts have no verified Arabic RTL/shaping. Privacy panel plainly reports unavailable account deletion, consent withdrawal and purchase restoration; it does not pretend those operations work.
- **Account separation:** Settings, chosen silhouette, story and mission preview fields live in the same UID-scoped preview profile mechanism as Hub progress. A more recent same-UID cache can replace preferences; same-day mission totals select one cache rather than add unverifiable values. Existing editor guest-stage QA now explicitly writes only to `LocalGuestHubRepository`, never an active account repository.
- **Tests:** `Phase9Tests.cs` covers schedule validation and fail-closed behavior, preference normalization, mission UTC reset, original roster/league/story boundaries and non-additive preview merging. Tests are authored but **not run** without Unity Test Runner.

## Precisely what is still missing / blocked

1. **Build acceptance:** Unity 6.3 import, generated scene assets, compilation, Test Runner, Android/iOS device builds, touch/safe-area/HUD layout, Arabic rendering, audio-focus coexistence and performance/long-run fairness testing. Unity, SDKs and devices are unavailable here. Fix any compile/runtime errors found in that pass.
2. **Production visuals/audio:** Rigged high-quality distinct player animations/body types, 3–5 unlockable outfit/colour variants per character, original team insignia/kit assets for 8–10 teams, accessories, boards, final environments/lighting/bloom/particles, fully produced soundtrack/SFX and video/cinematic boss/story. Current accessories, palettes, short text story and synthetic audio are greybox/provisional.
3. **Seasonal/live missions:** Actual x1–x30 mission multiplier integrated with verified score, upper-left in-run mission counter, server-approved daily progression, limited-time city/letter-hunt/festival content, limited seasonal characters/kits, 4–6-week free/premium pass. Existing Hub decor variants are static code; no remotely operated seasons or rewards.
4. **Showdown:** Authenticated 3–5-day event creation/scheduling, matching and asynchronous opponent runs, authoritative score/event validation, lifecycle, anti-cheat, exclusive winner unlocks, publisher tooling and real rollout. Only the optional, unreadable-until-configured public schedule is present.
5. **Rankings/prizes:** Server-computed scores from ordered gameplay events (never device totals), deterministic scoring, anti-cheat and implausible-run review, weekly/monthly close/reset/archive jobs, independently selected top-50 random award, top-three video verification, prize rules/compliance/fulfillment, real winner publications/shareable result art. Phase 8 is read-only, fail-closed; **no standings, winners or prize draws have been fabricated.**
6. **Economy/ads/IAP:** Secure server wallet and inventory ledger, actual rare gems/keys/boxes, unlockable shop catalogue and prices, receipt verification/store billing, purchase restore, 60/40 unlock design, ad SDK rewarded callbacks/limits/streaks and between-run interstitials, age/consent gating. Existing Market/wheel coins are explicitly local guest demos; ad gateways are disabled. No spendable account rewards or real-money offers are enabled.
7. **Accounts/privacy:** Install and configure Firebase, Google/Apple/Game Center credentials and platform entitlements, deploy/test Firestore rules/emulator, verified account profile and cloud conflict QA, delete/export/consent-withdrawal flows, privacy policy, actual purchase restore and any required Facebook provider. The privacy panel is informational, not a substitute for compliance.
8. **Full localization/accessibility:** Translate **every** run/Hub/store/account/error/league/mission string, proper Arabic shaping and RTL layout with licensable fonts, French/Arabic proofreading, regional compliance and accessibility QA. Current selection translates a limited navigation/story/settings subset; English default avoids silently unreadable default Arabic text until font validation.
9. **Separate repository:** A separate GitHub repo was requested but `createRepository` was denied by integration; per owner instruction, do not retry until permissions are resolved. The game stays isolated at `games/ultimate-football-chase/` in this branch.

Security boundary: `hubPreviews/{uid}` and all client mission/run/skin fields are **not trusted** for rewards, purchases, matches or rankings. Example rules have **not been deployed**. The optional Firebase define is disabled by default. Never publish contest results from this prototype.
