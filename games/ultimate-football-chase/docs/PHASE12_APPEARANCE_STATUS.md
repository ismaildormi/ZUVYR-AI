# Appearance extension — source only

The owner requested additional original shirt colours, varied facial skin tones and optional headwear. The Unity source now stores **five complexion swatches** and **five independent headwear choices** (none, cap, band, visor, crest) in the same guest/UID-scoped **non-authoritative** Hub preview profile as the existing original characters and outfit colours. Wardrobe selections apply to Hub player, mannequin and runner, and malformed IDs fall back to safe defaults. No real-player likenesses, club branding, Subway Surfers assets, APK binaries or unlicensed source were imported. `Phase12Tests.cs` checks variant choice, save sanitization, visual toggles and account-cache merge; **Unity tests are authored but cannot run in this environment**.

These are still geometric greybox add-ons—not rigged, textured 3D production models. Skin-tone options should not be mistaken for a finished character-creation system or legal reuse of a cloned game's models. The [third-party audit](OPEN_SOURCE_REUSE_AUDIT.md) explains why the suggested unlicensed Unity template was not copied. The only explicitly MIT Unity clone examined has script snippets but lacks playable scenes, character meshes, animation and project settings; its difficulty system conflicts with the owner's specified 9 m/s and +3% per 100 m. Copying those scripts into this project would not deliver a tested or visually finished game.

To get the requested publishable build: independently licensed/original rigged characters and environment, proper assets/animations, Unity Editor compilation/Test Runner, Android/iOS device tests and platform/IP review are still required. This change does not imply app-store readiness or real-money features.
